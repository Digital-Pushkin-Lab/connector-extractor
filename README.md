# Извлечение линкеров

Извлекает из текста русскоязычные линкеры с помощью синтаксического парсинга
stanza и скоринга на основе правил. Вводные слова больше не выделяются в
отдельный тип: все коннекторы берутся из одного словаря `data/linkers.csv`
и получают метку `linker`.
## Установка

```bash
pip install -r requirements.txt
python -c "import stanza; stanza.download('ru')"   # разовая загрузка модели
```

## Файлы

- `data/linkers.csv` — словарь линкеров (собирается из
  `Коннекторы_правка.xlsx` скриптом `build_linkers_csv.py`).
- `build_linkers_csv.py` — пересборка `data/linkers.csv` из таблицы.
- `patterns.py` — превращает словарь из CSV в паттерны для сопоставления.
- `matching.py` — сопоставляет паттерны с токенами предложений, разобранных
  stanza.
- `rules.py` — скорер на основе правил (`RuleBasedLinkerChecker`), который
  оценивает, насколько найденный фрагмент похож на настоящий линкер, а не на
  случайное совпадение.
- `pipeline.py` — связывает парсинг, сопоставление и скоринг воедино, считает
  итоговую статистику, а также собирает движок (`build_engine`)
  и отдаёт спаны с символьными смещениями (`extract_spans` / `predict_spans`).
- `tables.py` — единое чтение и запись таблиц (`.csv` / `.tsv` / `.xlsx`).
- `extract.py` — точка входа для запуска из командной строки.
- `sentence_connectors.py` — разбивка текстов таблицы на предложения со
  списком коннекторов в каждом (см. ниже «Коннекторы по предложениям»).
- `evaluate.py` — оценка экстрактора на эталонном датасете с ручной разметкой
  (см. ниже «Оценка на бенчмарке»).

## Использование

```bash
# Одно предложение, JSON выводится в stdout
python extract.py --text "Более того, к Швеции отошли города Ивангород и Копорье."

# Текстовый файл
python extract.py --input-file article.txt --output result.json

# То же, но результат — таблица из одной строки (.csv / .tsv / .xlsx)
python extract.py --input-file article.txt --output result.csv

# Пакетный режим: анализ каждой строки колонки в CSV, запись CSV с добавленными колонками статистики
python extract.py --input-csv texts.csv --output results.csv                     # колонка выбирается автоматически
python extract.py --input-csv texts.csv --text-column text --output results.csv   # колонка задана явно
```

Файл `.csv` / `.tsv` / `.xlsx`, переданный через `--input-file`, тоже
читается как таблица (пакетный режим, как `--input-csv`), а не как один текст.
Любой другой файл в `--input-file` анализируется целиком как один текст.

В пакетном режиме тексты берутся только из одной колонки: из указанной в
`--text-column`, а если она не задана — из колонки с наибольшей средней
длиной строки (выбранная колонка печатается в stderr). Остальные колонки
переносятся в результат без изменений.

Прочие параметры:
- `--threshold` (по умолчанию `0.4`) — минимальная оценённая вероятность,
  при которой совпадение считается достоверным.
- `--linkers-csv` — указать альтернативный словарь.

## Формат вывода

Результат — это набор колонок (для `--input-csv` они добавляются к исходному
CSV, для `--text`/`--input-file` — тот же набор полей выводится как JSON, а
если `--output` оканчивается на `.csv` / `.tsv` / `.xlsx` — как таблица из
одной строки с колонкой `text` и колонками статистики).
Показатели "на 100 слов" считаются от числа не-пунктуационных токенов в
тексте.

| Колонка | Описание |
|---|---|
| `linkers_result` | сырые результаты по каждому предложению: список найденных линкеров с оценённой вероятностью |
| `unique_linker_count` | количество уникальных линкеров (с вероятностью ≥ `--threshold`) |
| `linker_count` | общее количество найденных линкеров (с повторами) |
| `unique_linkers` | список уникальных линкеров |
| `linkers_by_appearance` | список найденных линкеров по каждому предложению |
| `linkers_per_100` | `linker_count`, нормализованный на 100 слов |
| `unique_linkers_per_100` | `unique_linker_count`, нормализованный на 100 слов |
| `linkers_per_sentence` | среднее количество линкеров на предложение |
| `linkers_per_sentence_beginning` | то же для начала текста (первая треть предложений) |
| `linkers_per_sentence_middle` | то же для середины текста (вторая треть предложений) |
| `linkers_per_sentence_end` | то же для конца текста (последняя треть предложений) |

Текст делится на абзацы по переводам строки (пустые строки пропускаются),
а абзацы — на предложения с помощью razdel, так что предложение никогда не
переходит через границу абзаца. Если stanza делит предложение razdel на
несколько, линкеры из всех частей считаются линкерами одного предложения.

Деление на начало, середину и конец:
- Если в тексте несколько абзацев, текст делится по абзацам. Абзац короче
  5 слов (не-пунктуационных токенов) присоединяется к предыдущему абзацу, а
  короткий первый абзац (например, заголовок) — к следующему. Каждая часть
  получает все предложения своих абзацев.
- Если абзац один (в том числе после объединения коротких), текст делится
  по предложениям.

И абзацы, и предложения делятся на трети по одному правилу: начало и
середина получают по ⌈n/3⌉ единиц, конец — остаток, так что конец — самая
короткая часть (5 → 2 + 2 + 1). Короткие тексты: 1 → только начало;
2 → начало и конец (середины нет); 4 → 2 + 1 + 1. Во всех случаях в колонке
стоит среднее число линкеров **на предложение** в этой части. Для части без
предложений (и для текста без предложений) в колонке стоит `N/A`.

## Коннекторы по предложениям

`sentence_connectors.py` принимает таблицу (`.csv` / `.tsv` / `.xlsx`) с
текстами в колонке `text` и выдаёт таблицу, где каждая строка — одно
предложение:

| Колонка | Описание |
|---|---|
| `text_id` | номер строки текста в исходной таблице (1 — первый текст) |
| `sentence` | предложение (razdel, внутри абзаца) |
| `connectors` | коннекторы этого предложения по порядку, через `; ` (разрывный коннектор указывается один раз, например `если...то`) |

```bash
python sentence_connectors.py --input texts.xlsx --output sentences.csv
```

Предложения и коннекторы — те же, по которым `extract.py` считает
статистику на предложение (тот же порог `--threshold`, тот же словарь
`--linkers-csv`). Формат вывода определяется расширением `--output`. Пустые
тексты строк в выводе не дают.

## Оценка на бенчмарке

`evaluate.py` прогоняет экстрактор на датасете с ручной разметкой и считает
precision / recall / F1 / F2 для `linker`.

```bash
python evaluate.py                                   # src/benchmark3_all_linkers.xlsx
python evaluate.py --benchmark src/benchmark.tsv --threshold 0.4
python evaluate.py --status ERR --limit 100 --report src/debug.txt
```

Формат эталона (`.tsv` / `.xlsx`, колонка `text`): линкер заключается в
квадратные скобки с меткой — `[если]=linker`, `[правда]=other` (метка `other`
в метрики не идёт; метка `intro` из старых бенчмарков засчитывается как
`linker`). Хвост `0` (`[Если]=linker0`) помечает первую часть составной
конструкции; двойная метка (`[Действительно]=other=linker`) — верна последняя; строки, где `text`
начинается с `!`, считаются комментариями. Полный разбор формата — в шапке
`src/benchmark.tsv` и в docstring `evaluate.py`.

Сопоставление предсказанных спанов с эталонными — по символьным смещениям в
очищенном тексте, с запасным сравнением по поверхностной форме при частичном
перекрытии границ.
