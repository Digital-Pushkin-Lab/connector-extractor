# Отчёт о лабораторной работе

## Сравнение синтаксических парсеров (stanza и ruBERT) в экстракторе линкеров и вводных слов

Дата: 19 сентября 2026 г. Ветка репозитория: `bert-parser-comparison`.

## 1. Цель

Выяснить, изменится ли качество экстрактора русских линкеров и вводных слов, если синтаксическую разметку (часть речи, вершину и тип зависимости) от stanza заменить разметкой дообученной модели ruBERT с biaffine-классификатором `IuliiaPr/my-ruBert-parser-model`.

## 2. Задачи

1. Выяснить, как экстрактор отличает линкеры от вводных слов и какую роль в нём играет синтаксический разбор.
2. Изучить модель и обучающий блокнот, воспроизвести инференс модели.
3. Встроить модель в экстрактор так, чтобы словари, правила и метрики остались прежними.
4. Проверить корректность работы модели на золотой разметке UD.
5. Прогнать экстрактор на эталонном бенчмарке в трёх конфигурациях и сохранить результаты.
6. Проанализировать расхождения между конфигурациями.

## 3. Материалы и данные

**Экстрактор.** Текст делится на предложения (razdel), каждое разбирается stanza. Затем по словарям ищутся кандидаты, и каждый кандидат оценивается пятью правилами (начало предложения, маркеры зависимости `parataxis/discourse/cc/mark/fixed`, знаки препинания вокруг оборота и др.) плюс тремя дополнительными. Порог принятия — 0,4. Правила используют `head`, `deprel`, `upos` и признаки, вычисленные по соседним токенам (в том числе по леммам «а», «и», «же»); сопоставление со словарём идёт по словоформам.

**Словари.** `linkers.csv` — 988 выражений, `intro_words.csv` — 496. Тип найденного фрагмента определяется только тем, из какого словаря он взят: 228 выражений есть в обоих списках, и для них побеждает `intro` (небольшая надбавка +0,01 к вероятности), 268 выражений встречаются только среди вводных слов. Сами правила для двух типов одинаковы.

**Бенчмарк.** `src/benchmark2.xlsx`: 84 предложения с ручной разметкой (без строк-комментариев), 65 линкеров и 27 вводных слов.

**Модель.** ruBERT-base (`ai-forever/ruBert-base`) с тремя головами: UPOS, вершина, тип зависимости. По блокноту, она обучалась 8 эпох на первых 80 % файла `ru_taiga-ud-train-a.conllu` (UD Russian-Taiga, 25 377 предложений). Ревизия модели на Hugging Face — `43b11a88`. Лемм модель не предсказывает.

**Среда.** Python 3.8, torch 2.0.0, transformers 4.20.0, stanza 1.4.0; вычисления на CPU.

## 4. Ход работы

**4.1. Три конфигурации.** Токенизация и леммы во всех вариантах берутся из stanza; меняется только источник разметки:

- `stanza` — `upos`, `head`, `deprel` из stanza (базовый вариант, поведение не менялось);
- `bert` — все три признака из ruBERT-парсера;
- `bert-deps` — `head` и `deprel` из ruBERT, `upos` из stanza (отделяет вклад частеречной разметки).

Интеграция сделана обёрткой над конвейером stanza (`bert_parser.py`), поэтому сопоставление и правила не менялись. Выбор парсера — параметр `--parser` в `extract.py` и `evaluate.py`.

**4.2. Особенности модели, учтённые при интеграции.**

1. В репозитории модели нет списков меток. Их восстановили по обучающему файлу так же, как в блокноте (отсортированные уникальные значения): получилось 17 UPOS и 51 тип зависимости, что совпало с конфигурацией модели.
2. Вершины закодированы позицией подслова, причём со сдвигом на одно слово. Поэтому предсказанную позицию переводят в номер слова, а к предложению без финальной пунктуации добавляют точку (иначе последнее слово не может быть вершиной).
3. Модель загружается собственным кодом, без `trust_remote_code`: так никакой чужой код не исполняется, и работает старая версия transformers из Python 3.8.
4. Метки Taiga с подтипами (`parataxis:discourse`) правила не распознают, так как сравнивают `deprel` с базовыми названиями. Для ruBERT подтип отбрасывается; правила не менялись, чтобы не затронуть базовый вариант.

**4.3. Проверка корректности.** Модель запускалась на валидационной части обучающего блокнота (последние 20 % файла: 5 076 предложений, 109 992 слова), которую она не видела. Первый прогон дал POS 0,942 / UAS 0,922 / LAS 0,891 против 0,995 / 0,959 / 0,946 в блокноте. Причина нашлась в токенайзере: в репозитории базовой модели нет `tokenizer_config`, и transformers 4.20 по умолчанию приводил текст к нижнему регистру, хотя словарь ruBERT чувствителен к регистру (25 927 записей с заглавной буквы). После установки `do_lower_case=False` результаты совпали с блокнотом.

**4.4. Оценка на бенчмарке.** Из бенчмарка удаляется разметка, очищенный текст подаётся экстрактору, предсказанные фрагменты сопоставляются с эталонными по символьным смещениям (запасной вариант — совпадение поверхностной формы). Считаются precision, recall, F1 и F2 (micro) для `linker`, `intro` и `connector` (оба типа вместе). Порог, словари и правила одинаковы во всех конфигурациях.

## 5. Результаты

**5.1. Проверка модели на золотой разметке UD** (5 076 предложений):

| | POS | UAS | LAS |
|---|---|---|---|
| Наш инференс | 0,9946 | 0,9577 | 0,9449 |
| Блокнот | 0,9946 | 0,9593 | 0,9464 |

Остаточное отличие около 0,15 п. п. по UAS и LAS, вероятно, связано с тем, что блокнот обрезал предложения до 128 подслов, а мы — до 512 (эта причина не проверялась отдельно).

**5.2. Экстрактор на бенчмарке** (84 предложения):

| Конфигурация | linker P / R / F1 | intro P / R / F1 | connector F1 |
|---|---|---|---|
| stanza | 0,981 / 0,800 / 0,881 | 0,730 / 1,000 / 0,844 | 0,945 |
| bert | 1,000 / 0,800 / 0,889 | 0,730 / 1,000 / 0,844 | 0,950 |
| bert-deps | 1,000 / 0,800 / 0,889 | 0,730 / 1,000 / 0,844 | 0,950 |

**5.3. Совпадение разметки** stanza и ruBERT на 909 токенах бенчмарка: POS 96,4 %, вершины (UAS) 97,8 %, вершины с типом (LAS) 91,1 %. Из 33 расхождений по POS 12 приходится на слова вроде «правда», «значит», «очевидно», «увы», «видно» (ADV / NOUN / VERB / ADJ), большинство остальных — на разную трактовку ADJ, DET и NUM («одной», «другие», «другой»).

**5.4. Расхождения.** Предсказания различаются лишь в 3 предложениях из 84:

- № 62: ruBERT не находит верный оборот «как и» (хуже);
- № 88: ruBERT правильно отвергает «При этом господине», где stanza даёт ложное срабатывание (лучше);
- № 19: ruBERT верно находит «что», но «настолько» пропущено обеими конфигурациями, поэтому строка остаётся ошибочной (лучше, но не полностью).

## 6. Обсуждение и выводы

1. Замена парсера практически не влияет на результат экстрактора: единственное изменение метрик — на одно ложное срабатывание меньше у `linker` (0,981 → 1,000 по precision), а recall и все показатели `intro` совпадают.
2. Варианты `bert` и `bert-deps` дают одинаковые результаты, поэтому частеречная разметка модели на этом бенчмарке роли не играет.
3. Основные ошибки не зависят от парсера: число пропущенных линкеров (13) и ложных вводных слов (10) одинаково во всех конфигурациях (в №19 и №62 меняется лишь состав найденных фрагментов). Их причины — словари и правила (в том числе то, что тип определяется словарём), а не синтаксис.
4. Ограничения. Бенчмарк мал (различия в трёх предложениях, статистическую значимость установить нельзя). Правила разрабатывались поверх разметки stanza, что могло слегка занижать результат ruBERT (это предположение). Модель обучена на Taiga, а не на текстах бенчмарка. Кроме того, память модели растёт квадратично от длины предложения.
5. Рекомендации: расширить бенчмарк, прежде чем выбирать парсер; ruBERT-парсер можно использовать вместо `depparse` stanza без заметной потери качества на этом бенчмарке (скорость мы надёжно не измеряли); для улучшения самих метрик стоит пересматривать правила и словари.

## 7. Воспроизведение

```bash
conda activate py38 && pip install -r requirements-bert.txt
python compare_parsers.py                                  # три конфигурации, результаты в results/parser_comparison/
python validate_bert_parser.py --conllu ru_taiga-ud-train-a.conllu   # проверка на золотой разметке UD
```

Файлы результатов: `summary.txt`, `metrics.csv`, `debug_<парсер>.txt`, `differences.txt`, `validation_heldout.txt`.
